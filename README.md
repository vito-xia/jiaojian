# 交件监控中心

这是一个可离线运行的静态交件超时看板。页面不依赖 CDN 或外部接口，数据不会主动上传；生成数据后可直接双击 `dashboard.html` 打开。

AI 或新协作者接手时，请先完整阅读 [`AGENTS.md`](AGENTS.md) 和 [`项目交接文档.md`](项目交接文档.md)。前者定义协作与冷启动规则，后者记录当前业务口径、视觉契约、运行方式和待确认事项。

## 更新数据

1. 将手工维护的 Excel 放入 `数据源/数据源-手动更新`；T-1 下载结果、T 日下载结果和超长单处理结果分别由脚本写入 `数据源/脚本处理后输出`，保持文件名和表结构不变。
2. 首次运行时安装依赖：`python -m pip install -r requirements.txt`
3. T-1 推荐双击 `数据源/更新T-1数据源.bat`；它会先下载并截取 T-1 文件，再调用根目录全流程更新看板。也可双击 `更新看板数据.bat` 只执行已有源文件的处理与构建。
4. `更新看板数据.bat` 会生成常规 `data/` 和 `data/抖音高停滞积分网点.xlsx`，合并超长单历史并生成 `data/dashboard_long_order.js`，再构建普通静态站点与 Worker 包；命令行运行时可加 `--no-pause`。
5. 双击 `dashboard.html` 查看。

如需指定 T-1 数据日：

```powershell
python process_data.py --as-of 2026-07-26
```

`process_data.py` 默认以 `数据源/脚本处理后输出/交件T-1脚本处理后` 中的最大日期作为 T-1，并从 `数据源/数据源-手动更新` 读取②至⑥及超长单源，输出到 `data`。Excel 只包含抖音最新看板日期及此前 14 个自然日内可选日期的全部高积分网点，标记每行相对所属看板日期的 T-1/T-2，按日期降序、同日最近扣分日单量降序；看板可选日期范围不因此缩短。超长单脚本从 `数据源/数据源-手动更新/超长单-手动更新` 读取新增日期，处理后目录保留历史副本并参与趋势分片生成；可用 `--source-dir` 指定其他目录，`--check` 只校验不写入。单独运行超长单脚本后，需运行常规更新入口才能同步高积分新列与 Excel。

T 日入口位于 `数据源/更新T日数据.bat` 和 `数据源/下载T日数据.bat`，实际 Python 逻辑集中在 `数据源/脚本/T/`，根目录不再保留重复入口。生成 T 日看板前会检查 `数据源/数据源-手动更新/交件链接清单T日.txt` 与 `数据源/数据源-手动更新/T日内网轨迹.xlsx` 的最新修改日期；任一文件不是本机当天修改时跳过更新并保留原有分片。

## 已固化口径

- ①交件超时：G/H/J/K/L/M 分别为 24/36/48/72/96/120H 超时量，I 为已省略 `%` 的 36H 超时率。
- 停滞积分：T-16 至 T-1 内，“物流停滞-揽收端”与“物流停滞-全链路”的“当前违规积分”之和。
- 历史缺货：分部先匹配一级公司，再按平台、月份统计一级公司所有下属分部的不同上榜日期数。
- 历史清退：商家 ID 为空、管控动作是“限制面单取号”、状态包含“执行中”或为“已完结”；按一级公司汇总。
- 近期管控店铺数：商家 ID 不为空且状态包含“执行中”的记录条数。
- 客户排除：客户名称包含“温宿韵通达”、“新疆”或“北亩”时，不进入交件榜单、客户趋势、历史缺货和相关KPI。
- 平台范围：支持抖音、淘宝、京东、快手；交件文件按“平台_月日.xlsx”命名，新增文件后会自动进入对应平台。
- 平台字段：仅抖音展示停滞积分、平台管控与清退字段；高停滞积分网点在首次上榜当天及次日连续标记 NEW，并按滚动 16 天内揽收端 0/1/2 分记录对应的发运超时异常单量日均展示扣分量级，仅有全链路积分时显示“超长单扣分”。新增“近期超长单量级”按近 15 天有数值的超长单异常运单数日期计算日均，真实 0 计入、缺失不补零；看板继续按积分排序。平台模块同时展示近一个月积分中异常等级为“极端异常”的最近 20 条熔断记录。
- 交件预警：抖音展示当日 TOP60，默认每页 10 条，可切换为 20/30 条；暂不设置上榜阈值。淘宝、快手仍展示 TOP10，京东沿用 TOP60 与现有上榜阈值。
- 日期窗口：抖音、淘宝、快手使用 T-7 至 T-1；京东使用 T-8 至 T-2，并默认选中当前可用的 T-2 数据日。
- 平台模块检索：抖音“平台预警与管控”支持按网点、一级公司、管控动作和状态筛选两张现有表。
- 历史缺货明细：点击网点后，抖音和淘宝按当前平台关联“②揽收环节上榜管控清单”，只展示所选 7 天窗口内超时原因和整改动作均非空的记录；京东和快手不展示原因与整改动作。
